# ADR-001：DDD 模块化单体，借鉴 ABP vNext 模式但不锁定框架

- 状态：**已接受**
- 日期：2026-11-04

## 背景

平台必须"高度灵活、可扩展"（需求 9），并参考 ABP vNext。候选方案：

1. 整体采用 ABP 框架（含其模块系统/启动模板）。
2. 借鉴其成熟模式（DDD 分层、仓储抽象、规约、模块插件、UoW），自研轻量基础设施。
3. 放弃 DDD，做传统的分层应用。

## 决策

采用方案 2。以 ABP vNext 为**模式参考**：模块各自负责 DI 注册；领域层定义仓储接口、由 EF Core 基础设施实现；跨聚合逻辑放在领域服务；用例由工作单元包裹。

## 后果

- **优点**：无框架版本锁定；体量小，契合 Blazor WASM 独立部署；每个模块后续可平滑拆分为微服务。
- **缺点**：ABP 免费提供的少量管道（模块加载器、UoW 装饰器）需自行实现——工作量有界且有测试覆盖。
- 新增模块或语言永远不会波及无关模块。
