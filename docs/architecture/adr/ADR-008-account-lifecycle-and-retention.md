# ADR-008：账户生命周期、邮箱验证与数据保留

- 状态：已接受
- 日期：2026-11-14
- 关联：ADR-004（服务端权威数据）、ADR-005（SQLite）、ADR-006（身份提供方）

## 背景

第 3 阶段实现了注册/登录/会话（ADR-006），但没有邮箱验证、密码找回、账户注销、数据导出与数据保留策略。公开上线前必须补齐：账户恢复能力（否则忘记密码即永久失联）、个人数据权利（注销与导出）、以及可解释的数据保留期。

## 决策

### 1. 邮箱验证

- **验证码**：6 位数字，30 分钟有效，一次性；散列（SHA-256 + 盐）后存库，明文只出现在邮件中。
- **错误尝试**：同一验证码最多 5 次失败尝试，超过即作废。
- **重发**：同一邮箱每小时最多 5 次；重新申请立即作废旧验证码。
- **登录策略**：配置 `Identity:RequireVerifiedEmailForLogin`（默认 `true`）。为 `true` 时注册不签发令牌，未验证账户登录返回 `Identity:EmailNotVerified`；为 `false` 时注册即签发令牌，验证只作为后续加固手段。
- **迁移兼容**：本决策上线前已存在的账户在迁移时回填 `EmailVerifiedAtUtc = RegisteredAtUtc`，避免存量用户被锁定。

### 2. 密码找回

- **不泄露账户存在性**：`POST /api/identity/password/forgot` 对任意输入都返回 202；只有账户存在且有效时才实际发送验证码。
- **重置即验证**：成功重置密码会将邮箱标记为已验证（持有验证码即证明邮箱控制权）。
- **会话吊销**：重置成功后吊销该账户全部会话（复用 ADR-006 的会话活性校验）。

### 3. 账户注销（删除权）

- 重新输入密码确认；服务端执行：
  1. 删除身份关联、凭据、账户令牌、全部会话；
  2. 删除全部学习数据（学习配置、学习活动、复习卡、形态掌握度、进度投影）；
  3. 账户状态标记为 `Deleted`（标记删除，而非物理删除账户行）。
- **保留的匿名事实**：仅 `UserId`（随机 GUID）、注册时间、是否测试账户。它们不含邮箱/口令散列，且身份关联已删除后无法反向识别个人，用于累计注册数统计。该处理在下一次相关变更时经法律评审确认。
- 注销后同一邮箱可重新注册；旧访问令牌因会话失效立即不可用。

### 4. 数据导出

- `GET /api/identity/account/export` 返回本人 JSON：账户信息、学习配置、学习活动、复习卡、形态掌握度。
- 永远不导出：口令散列、令牌、会话标识、他人数据。

### 5. 数据保留期

| 数据 | 保留期 | 依据 |
|---|---|---|
| 账户、凭据、身份关联 | 账户存续期；注销时删除 | 提供服务所必需 |
| 学习活动 / 复习卡 / 形态掌握度 / 进度 | 账户存续期；注销时删除 | 学习进度由活动推导，不可提前清理 |
| 已结束会话记录 | 90 天 | 在线时长统计只需要近期数据 |
| 账户令牌（验证/重置） | 7 天（且使用/过期即作废） | 一次性凭据 |
| 匿名注册事实 | 永久 | 累计注册数统计，不含个人信息 |
| 邮件发件箱（仅开发/测试环境） | 进程内存，不持久化 | 调试用途 |

- 清理由 `BeafSoup.DbMigrator purge` 命令执行（幂等），生产部署须以定时任务调度；在引入后台作业基础设施前不内置调度器。

### 6. 邮件发送抽象

- `IEmailSender` 定义在 Identity.Application.Contracts，宿主负责实现。
- 仓库内提供 `DevelopmentEmailSender`：仅在 `Development` / `Testing` 环境启用，把邮件写入进程内发件箱，并通过 `/api/dev/email-outbox`（仅在同样环境暴露）供开发与自动化测试取验证码。
- 生产环境必须接入 SMTP 或邮件服务商实现；未配置时登录/找回流程会明确失败，不会静默吞掉验证码。

## 后果

- 注册与登录多一步验证；在开发环境用发件箱端点即可完成端到端流程。
- 上线仍需：真实邮件发送实现、邮件模板本地化、法律评审隐私政策文本、对注销/导出行为进行合规确认。
- 数据保留期清理依赖运维调度；未调度时数据只增长不删除，不会产生错误行为。
