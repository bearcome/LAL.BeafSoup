# ADR-004：服务端权威数据与静态 WASM 客户端

- 状态：**已接受**
- 日期：2026-11-04

## 背景

Blazor WASM 客户端独立静态部署，但首发还要求注册账户、跨请求账户归属校验、集中学习进度及服务端在线统计。浏览器内数据库无法作为跨设备、跨会话的权威来源；客户端时间和客户端上报的累计时长也不可信。

## 决策

- `HttpApi.Host` 是用户账户、学习配置、学习活动、复习状态、考试记录及使用统计的权威读写入口；其持久化实现位于服务端基础设施层。
- Blazor WASM 发布物保持纯静态，可与 API 独立托管；音频仍由静态资产 URL 提供。
- 浏览器存储仅作为可丢弃缓存，不接受离线学习写入作为权威状态，不做未经确认的自动冲突合并。
- 所有用户数据访问均以经过验证的服务端身份为主体；客户端提交的 `UserId`、时间戳、统计计数不得作为授权或统计依据。
- 本 ADR 不指定数据库产品、身份提供方或云供应商；这些选择分别在对应阶段通过 ADR 决定，不得由实现者自行引入依赖。

## 后果

- 注册、账户隔离、学习进度及在线统计可以跨设备保持一致，并由服务端实施安全策略。
- 产品首发需要运行和监控 API 与服务端存储；纯静态托管本身不足以运行完整产品。
- 离线写入、冲突解决、数据导出/删除和备份恢复策略须在启用对应能力前单独设计。
- API 契约与仓储抽象隔离具体存储技术；服务端故障时客户端应明确显示不可用/重试状态，不伪造成功写入。
