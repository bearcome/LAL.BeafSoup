# ADR-005：SQLite 作为服务端权威数据库

- 状态：**已接受**
- 日期：2026-11-06

## 背景

ADR-004 决定账户、学习配置、学习活动、复习状态、考试记录与使用统计由服务端权威持久化，但有意不指定数据库产品（Q1）。第 2 阶段需要落地内容与本地化数据层 Schema，必须先决定供应商、备份与迁移策略。

候选：SQLite、PostgreSQL、SQL Server。本应用写路径以学习作答、心跳等中小并发为主，读路径以内容查询为主；预算约束为免费额度。

## 决策

- 权威数据使用 **SQLite**（`Microsoft.EntityFrameworkCore.Sqlite`），每个部署一个数据库文件；连接串仅存在于服务端配置，绝不进入 WASM 产物。
- 每个模块保留自己的 `DbContext` 与 EF 迁移（`{Module}.EntityFrameworkCore`），多个模块上下文共享同一个数据库文件，各自使用独立的迁移历史表（`__EFMigrationsHistory_{Module}`）；跨模块引用（如词形 ID、语义键）不在数据库层建外键，由种子/发布管线的领域校验保证一致性。
- 备份策略 = 文件级备份：备份前执行 WAL checkpoint，直接复制数据库文件；每日保留策略由部署方决定，代码不提供自动备份。
- 迁移策略 = EF 迁移，随服务端启动由迁移工具（`BeafSoup.DbMigrator`）显式执行，应用运行期不做自动 `Migrate()`；破坏性迁移必须先出数据迁移说明。
- Schema 变更（新增列/表）遵循"先加后移"：新增可空 → 双写/回填 → 后续迁移删除旧列。

## 后果

- 零额外服务进程与托管成本；本地开发、CI 与生产使用同一存储引擎，消除环境差异。
- 单写者吞吐有上限（WAL 模式下单写多读）：学习类负载足够；若未来出现统计聚合或多写者需求，需重新评估（替换点被限制在各模块 `EntityFrameworkCore` 项目内，领域层不受影响）。
- 数据库文件随部署分发，必须确保备份与迁移脚本进入运维清单；文件损坏时从最近备份恢复。
